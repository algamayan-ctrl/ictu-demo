SPMU-ACPMP — FINAL CROSS-DEVICE EMAIL VERIFICATION FIX
========================================================

WHAT THIS FIX SOLVES
--------------------
The old verification email could contain:

    http://127.0.0.1:8080/email/verify/...

That address can never work correctly from another physical device because
127.0.0.1/localhost always means "this device".

The fixed flow is:

    ICTU creates account
       -> account is saved
       -> verification email is sent automatically
       -> recipient opens email on phone/laptop/tablet
       -> Verify CSPC Email goes to ONE shared SPMU-ACPMP server
       -> account is verified

No command is run after each registration.

CHANGES INCLUDED
----------------
1. Verification links use host-independent Laravel signatures.
2. localhost / 127.0.0.1 are rejected for cross-device email links.
3. ICTU System Configuration now has a one-time "Verification Address" field.
4. If SPMU is already opened through a reachable LAN IP/domain, that shared
   request address may be used automatically.
5. The raw Laravel 404 caused by missing implicit User route binding is removed.
   A stale/wrong-server verification link now redirects to Login with a proper
   verification error message instead of showing "404 Not Found".
6. Old absolute-signed links remain accepted when they still point to the
   correct server.
7. Registration and Resend Verification remain automatic.

INSTALL
-------
Copy/replace all files from this ZIP using the same folder paths.

Then rebuild/recreate the Laravel containers:

    docker compose up -d --build --force-recreate app scheduler queue

The included migration is applied automatically in this project's current
Docker setup because RUN_MIGRATIONS=true.

ONE-TIME SYSTEM SETUP
---------------------
Login as ICTU and open:

    System Configuration
      -> Verification Address

Set ONE shared SPMU-ACPMP URL.

For an actual deployed system accessible from any network:

    https://<your-real-spmu-domain>

For a capstone demo where all devices are on the same Wi-Fi/LAN:

    http://<SERVER-LAPTOP-IP>:8080

Example only:

    http://192.168.1.50:8080

Do NOT enter localhost or 127.0.0.1. The application now rejects them.

This is a ONE-TIME server configuration, not a step performed for every user.

AUTOMATIC BEHAVIOR AFTER THAT
-----------------------------
For every new ICTU registration:

    Create Account
      -> automatic verification email
      -> recipient opens email from any reachable device
      -> clicks Verify CSPC Email
      -> account verified

No .cmd, PowerShell, or manual per-account URL setup is required.

IMPORTANT ABOUT "ANY DEVICE"
----------------------------
The recipient device must be able to reach the configured SPMU-ACPMP address.

A 192.168.x.x / 10.x.x.x LAN address normally works only on the same local
network. If verification must work from mobile data, home Wi-Fi, or any outside
network, deploy SPMU-ACPMP on its approved HTTPS domain/server and enter that
HTTPS URL once in Verification Address.

TEST WITH A NEW EMAIL
---------------------
Previously sent messages still contain their old URL. After installing this
fix, create a new test account or use Resend Verification so a NEW email is
generated.
