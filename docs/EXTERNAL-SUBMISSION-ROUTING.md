## Implemented changes

Added `SubmissionEvidenceService`: readable PDFs are checked through the installed FPDI parser and image bytes through the installed image decoder; persisted private evidence must exist and match its stored size/hash. The controller validates document readability before writes. Required-document checks also verify current request/version/borrower linkage. `SignatureService` reads/validates the authenticated signer's own current image before capturing its immutable snapshot.

Submission locks/refetches the header and rechecks ownership/editability before loading/signing its version. Draft edit, supporting-file metadata and final submission now share the same transaction. The private file writer rejects failed writes and registers installed Laravel `afterRollBack` callbacks for only newly allocated UUID paths, including nested transactions; metadata creation failures also clean up the newly created bytes. Registration translates a private-write failure to its existing Valid ID validation error. Submission and SAO-forwarding notices exclude inactive/unverified/unapproved/revoked-role staff while preserving the existing current-stage recipient classification. Borrower detail now exposes existing authorized preview links for current final operational documents.

Added `ExternalBorrowingSubmissionTest` and reusable `Tests/Support/EvidenceFixtures` with genuine synthetic PDFs/PNG images. Updated three old signature/document fixture helpers and stale PTC/pickup-copy assertions. The off-campus release test now models a fresh officer session after its multi-day time jump and asserts the successful release redirect; the idle protection and release rules were retained. No migration or approval-authority change was introduced.

## Usage, checklist and gate

1. Review/apply the existing S1-REG-01/02 migrations normally to a backed-up development/staging database when integrating those earlier increments. This task adds no migration and did not migrate the working/live database.
2. Complete external registration, mailbox verification and SAO approval. Register the borrower's own readable E-signature in Account Settings.
3. Prepare the request using its reviewed company, valid dates and configured eligible items. Attach the approved activity/request letter and PTC if student activity. Draft saving is still available without the required submission set.
4. Check the certification, review the final confirmation, and E-sign/submit. On-campus enters Admin review; off-campus enters SAO verification before Admin. SAO verification alone never reserves inventory or grants final approval.
5. Review the recorded company/signature/document/status/audit and the correct reviewer queue. Failed edit/submission must preserve the existing draft and historical evidence; concurrent submissions must leave one official signing action.
