# Manual report signatories revision — 16 November 2026

The user approved printed names and blank lines for manual signatures on all six visible report types. This implements RSC item 5 without electronically signing reports or introducing a new approval workflow.

## Result

- **Prepared by:** the active SPMU Action Officer's printed name and recorded designation, on the left.
- **Noted by:** the active SPMU Admin/Head's printed name and recorded designation, on the right.
- Blank handwriting space and a signature line above each name. Names are uppercase and underlined in the outputs; account records are unchanged.
- The signatory block appears once after the report records and stays together at page boundaries in print/PDF/Word. Excel places both signatories in one row outside the sortable record range and fits the print width onto one page while allowing additional vertical pages.
- Preview/Print, PDF, Word and Excel use the same signatory metadata. CSV remains the original structured data export.
- Generator metadata is labelled **Generated by**, separately from the designated preparer. The obsolete **No signature is required** statement is removed, including from the PDF's separately stamped page footer. Actual page numbering is preserved.

There is one active account for each signatory role in the current native instance. The resolver reads existing profiles and excludes inactive/suspended accounts. Missing designations fall back to the corresponding role label. Missing or multiple eligible accounts display **Signatory not designated**, rather than choosing a person arbitrarily. Profile details are captured in each generated dataset; output renderers do not substitute a later profile change into that dataset.

The Word signatory table is unboxed. Excel retains the data-derived column widths, partitions signatory cells by their physical widths, wraps their text in a sufficiently tall shared row, and fits the print width to one page. These are presentation changes for the approved signature area; record values, number/date cell types, table filters and frozen headings remain preserved.

The DOM checks use JSDOM and the shipped report updater. They are not authenticated desktop/mobile browser screenshots. Existing browser-tool connection problems do not invalidate file-based export checks, but actual browser/user acceptance is recorded separately.
