## SAO demonstration checklist

Use clearly identified test records in the separate ICTU demo. Keep existing records and do not copy real personal information or production transactions into the demo.

| Scenario | What the SAO should be able to demonstrate |
| --- | --- |
| On-campus request | Direct Head review; no unnecessary SAO verification step. |
| Off-campus request | Supporting-document review, full-screen preview and explicit SAO verification before Head approval. |
| Incomplete or unclear document | Return for revision with specific corrections; revised version remains traceable. |
| Approved request | Preparation and scheduled pickup in Release. |
| Missed pickup | Visible exception, without treating the items as released. |
| Physical release | Recorded handover and the same travelling printed Borrower Slip. |
| Non-linen return | Actual received quantity, condition and return date. |
| Linen awaiting a form | Awaiting Laundry Form; no fabricated Laundry Worker portal activity. |
| Accomplished Laundry Form received | Record the signed form's received date, then record the return in the existing Return page. |
| Completed good linen | Recorded return, correct available quantity, form preview and no redundant tracker. |
| Late return | Distinguish outstanding Overdue items from a returned-late record and a resolved historical finding. |
| Damaged/lost item or mixed findings | Specific condition and case reason; only serviceable quantities become available. |

## Team coordination

- Work stays on feature/action-officer in the separate ictu-demo checkout. No commit, push or production change is included in this pass.
- Role branches can still conflict when they edit a shared file. Coordinate changes to layouts, document components, request views, routes and common services before integration.
- SAO-specific pages include registrations, verification views, Release/Return, Laundry, Gate Pass and SAO accountability presentation. Some of these live in shared request/custody files and must keep role checks.
- SAO Inventory Overview uses a compact stock summary and three tabs: Overview, Stock Card and Borrowing History. Item information is included in Overview. Zero-value breakdowns are collapsed; actual stock findings open automatically, and related source records and history remain accessible. Inventory calculations and SAO read-only permissions are retained. Admin and Borrower detail layouts keep their own presentation.
- SAO Stock Card presents chronological receipts, issues, office, and running balances, with search, movement filters, and pagination. Both screen and print follow the supplied paper's item-information grid and grouped Receipt/Issue/Balance headings, followed by No. of Days to consume. Fund Cluster, Stock No., and Re-order Point remain blank because no corresponding values are stored; the system inventory ID is not substituted for an official stock number. Consumption days remain blank for borrowing records. Dates use MM-DD-YYYY and the unrequested Remarks column is removed; its source notes remain searchable and available on reference-cell hover. Reservations and internal laundry/repair transfers do not create a second receipt or issue. Retained stock includes reserved units and returned units under laundry/repair, while borrower custody and missing/destroyed quantities are excluded. Inferred starting quantities are used only to calculate running balances and are not displayed as transactions. Actual recorded opening-stock receipts remain visible. Unreconciled balances remain blank with a review notice. Print Stock Card opens an optional internal print copy of every matching entry, regardless of the displayed page. The unrequested Prepared/Checked signature block was removed to follow the supplied reference. No controlled form number, fund cluster, reorder point, consumption figures, or signature image is invented. Admin retains the original ledger presentation.
- This pass touches the shared document viewer with a SpmuOfficer condition; Admin and Borrower controls are retained. Request Records pagination is also conditional on the SAO role.
- Earlier comment cleanup spans shared and other-role files. A filename in the current diff is not proof that its whole contents belong to the SAO owner. Review that cleanup separately from functional role changes.
- Coordinate with the Borrower owner for submission/resubmission and user-facing notices, and with the Admin owner for approval, report signatories, audit filters and Configuration navigation.

## Verification scope

The SAO pickup card uses one contextual heading and one instruction with its available actions. A missed pickup with time remaining asks the officer to confirm the borrower's arrival; a closed pickup period asks for cancellation rather than also suggesting confirmation. Routine sent-notification text and repeated review headings are omitted; notification failures remain visible. Delayed-approval dates and the next pickup time remain in the collapsed Schedule details. The compact layout puts the instruction and actions on one row where space permits, and stacks them on small screens. Cancellation confirmation uses plain wording. These presentation changes do not alter pickup dates, cancellation permissions, stock or release validation.

Missed pickups and delayed-approval schedule reviews use the same Confirm Pickup action and arrival-confirmation dialog. The former Continue Release button is removed from the SAO screen. Both current forms explicitly record that the Action Officer confirmed the borrower is present, using the same arrival notice and history wording. Genuine missed-pickup provenance, preparation already completed, approved quantities, Date Needed limits and cancellation authority are retained. If no valid pickup remains, the confirmation is absent and authorized cancellation stays available. Older schedule-only submissions retain their original audit meaning and do not acquire an inferred presence attestation. Confirm Release remains the separate physical handover action.

The SAO Release record uses compact sentence-case headings and only purpose, date needed, return date and use location in its borrowing summary. It omits repeated borrower/requirement/reference labels, while retaining applicable documents and signature instructions. Schedule review has one Confirm Pickup button followed by a short confirmation dialog; the contact-attestation checkbox and contact note are removed from the current UI. The current dialog confirms that the borrower is present and will proceed with pickup. Its explicit presence flag records the SAO attestation, identity and time, and the notice acknowledges arrival rather than asking the borrower to visit again. Older schedule-only confirmations and actual contact notes retain their separate audit meaning. This confirmation does not prepare or physically release items, apply a borrower signature, or bypass the Date Needed limit. Older suggested/approval dates are collapsed under Schedule details. After Date Needed passes, an active authorized SAO may explicitly cancel an approved, unreleased request through the existing reason/confirmation flow; cancellation is never automatic. Issued items, future requests and unrelated approval/cancellation authority retain their guards. Release Confirmation remains visible before item preparation, with its checkbox, optional remarks and Confirm Release button disabled. A single short instruction explains the next action. Preparation and a valid pickup window are still required to enable the fields, and the signature checkbox must be selected before the release button is enabled. Server validation is retained. Viewing the page does not release items.

The SAO Release list uses a full-width records card that fills the remaining viewport, with horizontal row dividers and pagination at the bottom. Search, the existing four status categories, sort and page size update immediately. Filtering and sorting apply across all loaded eligible release records before ten-record pagination; page sizes are 10, 30, 50 and 100. A one-page result retains its range and disabled Previous/Next controls; no-results states hide pagination. The repeated Issued: Not yet field is omitted because the queue includes only unreleased transactions. View Record links retain the protected release route. Release selection, stock, pickup/preparation logic and other role/Return layouts are unchanged.

SAO Laundry Record uses one full-width card with a linen item table showing the item name/unit, issued quantity, physically returned quantity and condition counts. Lost, stolen and unreturned findings are shown as findings rather than physically returned quantities. The actual Laundry received date remains separate from the SAO record timestamp and named recorder, which come from the return transaction linked to the linen lines. Other non-linen returns in the same custody do not supply the recorder. The serviceable total is labelled Returned in Good Condition, and the accomplished form has a single View Form link. No tracker, new processing step or stock update is introduced by viewing the record.

SAO inventory labels use Allocated for approved quantities awaiting physical release, including the Inventory list, item summary, current source groups, request availability check, pickup confirmations, system-generated history wording and Stock Card print explanation. On Custody is retained. Shared views keep the other roles' wording. This is a presentation change only: allocation timing, quantities, availability, approval, release, database keys and stored historical records are unchanged.

The SAO Stock Card page omits the “About this record” disclosure. Balance calculations and unrecorded metadata are explained in this documentation rather than repeated beneath the table. The table, filters, pagination and Print Stock Card action are retained.

SAO Inventory Borrowing History shows borrower/office, release/due/return dates, issued/returned/to-return quantities, return status and any existing accountability finding, plus a View Details link to the protected custody record. The extra explanation banner, repeated summary boxes, purpose/location, schedule/time details, and duplicate reference columns are omitted from the SAO table; full records remain available through View Details. Search, dates, status and page size update the results without Apply Filter or Reset and without replacing the filter form. Filters apply before 10-record pagination and existing overlap/status calculations are retained. Head/Admin keeps the original presentation.

SAO Request Records keeps its range and Page 1 of 1 visible even when there are ten or fewer matching records. Previous/Next are disabled when there is no adjacent page. When no records match, the no-results message is shown instead. Search and Status are in the record list, rather than the summary-card Dashboard.

The SAO results card fills the remaining viewport height, with records at the top and pagination inside the card at the bottom. It grows naturally for longer lists instead of clipping rows. Other role layouts are retained.

Selected UI and workflow tests validate the changed controls, SAO signature consent and protected previews. These checks do not replace institutional approval or completion of the manual demonstration dataset.
